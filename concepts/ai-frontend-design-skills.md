# Дизайн-скиллы для AI-агентов: пять подходов

Срез README и доступных `SKILL.md` на **31.10.2026**. Это обзор заявленных процедур и требований, **не результат установки или сравнительного теста на одинаковом макете**. Эти инструменты дополняют [[agent-skills|общую практику скиллов]]: дизайн-решение должно исходить из задачи и реального материала продукта, а качество нужно проверять на отрендеренной странице, не только по коду. Связанные темы — [[ai-engineering|AI-инжиниринг]] и [[ai-motion-design|моушн-дизайн]].

## Что делает каждый

- **[Impeccable](https://github.com/pbakaus/impeccable)** — развитый набор команд для *уже существующего интерфейса*: `critique`, `audit`, `polish`, `bolder`, `quieter`, `harden`, `adapt` и другие. Помимо текстовых playbook, README описывает **62 детерминированных правила** выявления типовой AI-эстетики и ошибок качества; команды `init`/`document` фиксируют продуктовый контекст (`PRODUCT.md`) и визуальную систему (`DESIGN.md`). В актуальном [SKILL.md](https://github.com/pbakaus/impeccable/blob/2f97a85a4a87a80066a693bd3546b092bd300772/plugin/skills/impeccable/SKILL.md) различаются задачи убеждения, работы в приложении, чтения и визуального опыта. В README указана поддержка Hermes Agent. Лицензия — Apache-2.0. Ранее сохранённая в этой вики цифра **58 детекторов** относится к старой пересланной подборке; в проверенном README на дату среза указано **62**. ^[raw/articles/impeccable-readme-2026-10-31.md]
- **[Taste Skill](https://github.com/Leonxlnx/taste-skill)** (`design-taste-frontend`) — арт-дирекшн для *новых страниц и экранов приложения*. По заявлению автора, направления выведены из изучения 247 сайтов; скрипт предлагает три варианта из библиотеки, затем агент выбирает подходящий по особенностям клиента, подбирает реальные изображения и проверяет результат в браузере на нескольких ширинах с итерациями по скриншотам. Для рабочих экранов есть отдельный маршрут: правила для dashboard не должны автоматически наследовать требования к лендингу. Нужны Node 22+ и Chromium/Chrome/Edge; внешние изображения требуют сети. README предупреждает о ресурсоёмкости полного прохода. Лицензия — MIT. ^[raw/articles/taste-skill-readme-2026-10-31.md]
- **[unslop](https://github.com/heydamir/unslop)** — ручная поэтапная переработка уже созданного «вайбкодингового» UI: сначала аудит типовых признаков, затем согласуемое направление и проходы по отступам, цвету, иконкам, текстам, типографике, компоновке, деталям, изображениям и движению. Работает как инструкция для Claude Code в разных веб-стеках; может предложить генерацию изображения через внешний сервис, но README требует показать промпт и спросить перед платной генерацией. Дополнительный ролик требует Playwright и ffmpeg. Лицензия — CC BY 4.0, при адаптации и распространении нужна атрибуция. ^[raw/articles/unslop-readme-2026-10-31.md]
- **[Hallmark](https://github.com/Nutlope/hallmark)** — более полный pipeline *создания страницы с нуля* или редизайна по явной команде: три варианта из каталога **50 тем**, отдельная проверка hero, затем browser-lint на восьми ширинах и независимое ревью. Правила разделены на обязательный минимум (контраст, фокус, reduced motion, отсутствие выдуманных фактов, мобильная работоспособность), преодолимые шаблонные признаки и необязательную отделку. Редизайн должен сохранить содержимое и рабочие связи страницы; `/hallmark audit` только оценивает. Нужен Node 18+; для рендер-проверок — Chrome и `puppeteer-core`. Код MIT, но лицензии отдельных фотографий из каталога требуют внимания и указания авторства. ^[raw/articles/hallmark-readme-2026-10-31.md]
- **[AI Design Skills](https://github.com/elayadesign/ai-design-skills)** — пока **один** скилл `landing-page-design`, а не обширная библиотека: от брифа (оффер, аудитория, действие) и структуры/копирайтинга до конкретных правил шрифтов, отступов, скруглений, CTA, анимаций и состояний; [SKILL.md](https://github.com/elayadesign/ai-design-skills/blob/4fdcdd52f15eda09da1257c303c860c13e0c879f/skills/landing-page-design/SKILL.md) требует сначала план и тексты, затем код по секциям. Подходит как жёсткий шаблон лендинга, но его предписания по шрифтам и композиции стоит подчинять реальному бренду; примеры вымышленных имён, метрик и отзывов **нельзя выдавать за подтверждённые факты продукта**. Лицензия — MIT. ^[raw/articles/ai-design-skills-readme-2026-10-31.md]

## Как выбирать, а не складывать все правила вместе

1. **Проверить или отполировать существующий UI** → Impeccable (аудит/критика/точечные команды); unslop — если нужен осмысленный редизайн с явно утверждённым направлением. ^[raw/articles/impeccable-readme-2026-10-31.md] ^[raw/articles/unslop-readme-2026-10-31.md]
2. **Сделать новую выразительную страницу с визуальной проверкой** → Taste Skill или Hallmark: первый выводит направление из особенностей клиента и исследованных композиций, второй предлагает темы и формальные проверки «пола качества». **Рабочий dashboard** веди по app-маршруту, а не по правилам маркетинговой страницы. ^[raw/articles/taste-skill-readme-2026-10-31.md] ^[raw/articles/hallmark-readme-2026-10-31.md]
3. **Быстро структурировать конверсионный лендинг** → AI Design Skills, но не копируй механически обязательные блоки, заданные шрифты, градиент заголовка или требования к анимации, если они противоречат задаче/бренду/доступности. ^[raw/articles/ai-design-skills-readme-2026-10-31.md]

**Ограничения:** ни один проект здесь не установлен и не проверен на реальном приложении. Перед запуском стороннего `SKILL.md` и особенно скриптов, скачиваемых бинарников и хуков проверь команды, сетевые обращения, права и зависимости; изображения сверяй по собственной лицензии. Не запускай два взаимоисключающих набора визуальных правил на одной странице одновременно. Общее руководство по проверке сторонних скиллов — в [[agent-skills]].
